The problem

Two constraints that interact badly

Two-Headed Giant is a team format — you and your partner sit on the same side. The tournament's house rule says your two commanders must both have been printed in the same preconstructed deck set, and their color identities must not overlap. Reprints count, and any legendary card in the deck counts, not just the one on the box.

Neither rule is hard alone. Together they eliminate almost everything, and the surviving combinations are impossible to eyeball across 159 decklists.

Engineering

Three decisions that changed the answer

01 · Source of truth

Decklists, not set membership

The obvious query — every commander-legal card whose set is a Commander set — is wrong, and quietly so. Those set codes also cover Special Guests, booster-only cards and Jumpstart reprints that were never in a precon.

Eligibility now comes from actual decklists: a card counts only if it is physically one of the 100 cards. The same change correctly keeps cards whose printing carries the parent expansion's code.

02 · Rules that move

Delegate the ruling, don't reimplement it

Eligibility started as a local test: a legendary creature, or text saying it can be your commander. That is the kind of rule that looks correct and rots silently. A rules change made legendary Vehicles and Spacecraft legal commanders — and they carry no such text, so no wording test can ever find them.

Eligibility is now delegated to Scryfall's is:commander filter, which tracks rules changes on my behalf. Adopting it added 15 cards and removed none.

Grist is the tell. It is a creature card everywhere except the battlefield, has always been a legal commander, and predates the rules change entirely. The hand-written test had been silently dropping it the whole time — the local rule was unsound on its own terms, not just out of date.

03 · Trusting the wrong field

Parse oracle text, not the convenience field

Partner mechanics look like they should come from the API's keywords array. They can't. Every Partner with [name] card is tagged with a plain Partner keyword, and so is the restricted Partner—Character select. Building on that field makes cards partner that legally cannot.

A creature with a “partner with” ability can't partner with any creature other than its designated partner.

Mechanics are parsed from oracle text instead, and the illegal combinations are pinned directly in unit tests so the distinction can't regress.

Delivery

The answer had to be a spreadsheet

Players don't want a CLI. The deliverable is a workbook whose front page takes your picks and lists every commander your partner may legally bring — including partner pairs — with the shared set and which deck to buy it in.

Two constraints shaped the formulas. Portability: FILTER and XLOOKUP are “future functions” that need _xlfn._xlws. prefixes when a file is generated outside Excel, and render as #NAME? if you get that wrong. Sticking to INDEX/MATCH avoids the trap and keeps it working in Google Sheets, where it's been verified.

Cost: the partner list resolves its block position once, then reads by offset. 

// One MATCH per lookup, not one per row.
// Rows are pre-sorted so a commander's partners are contiguous.
M2 = MATCH($M$1 & "#1", 'Partner Options'!$B:$B, 0)   ← block start
M3 = COUNTIF('Partner Options'!$C:$C, $M$1)          ← block length

// each of 469 rows is then a pure offset read
A17 = INDEX('Partner Options'!$D:$D, $M$2 + ROW() - 17)

A per-row MATCH would rescan a 43,000-row table on every keystroke. The whole workbook contains 110 MATCH calls in total.

Confidence

Proving a spreadsheet actually works

openpyxl writes formulas but never evaluates them, so an off-by-one in an INDEX offset would ship looking perfect. Tests run in three layers, each answering a different question.

22
test_rules.py

Pure functions, no network, 0.2s. Pins the partner-legality matrix — especially the combinations that must not be legal.

19
test_workbook.py

Invariants over all 21,699 generated rows, checked against the source decklists rather than the build's own state, so a bug can't vouch for itself.

12
test_team_builder_excel.py

Opens the workbook in a real Excel instance over COM, types into the input cells, forces recalculation and compares what Excel computes.

The invariants are deliberately adversarial: no team may share a color, no card may appear on both sides, and every commander must trace back to a decklist of the set it claims. Two bugs were caught this way that no amount of reading would have found.

Findings

Some sets barely function

Once every team is enumerable, the format's shape becomes visible — and it is lopsided. This is the output people found most useful, because it tells you which sets to avoid before anyone spends money.
